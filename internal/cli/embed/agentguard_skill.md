# AgentGuard skill

AgentGuard is a single Go binary that proxies every MCP tool call this agent makes
and runs it through a defense-in-depth pipeline (transport → schema → attestation →
policy → content scan → ML → circuit breaker). It is **local-only** — nothing leaves
the machine. Your job, when invoked, is to set it up or operate it on the user's
behalf, doing the work they would otherwise do by hand.

The full CLI reference is `agentguard --help`. Docs: https://agentguard.space.

---

## First: is AgentGuard installed?

Run `agentguard --version`. If the command is not found, the user has not installed
the binary yet — tell them to run the one-liner from https://agentguard.space (it
auto-detects their OS) and come back. Do **not** try to install it yourself.

---

## Setup playbook — "I installed AgentGuard, set it up"

Do these in order. Every step is idempotent and safe to re-run.

1. **Health check.** `agentguard --version` then `agentguard doctor`. If `doctor`
   shows ✗ lines, fix or explain them before continuing (see Troubleshooting).
2. **Wire in this agent.** `agentguard init --non-interactive`. This detects the
   installed agents (Claude Code, Cursor, Codex, Gemini CLI, Windsurf), **backs up
   each config** to `<path>.agentguard.bak`, and rewrites every stdio MCP entry to
   route through `agentguard wrap`. Never hand-edit a config yourself — `init` does
   it safely and reversibly.
3. **Start the dashboard.** `agentguard dashboard --no-browser`, then give the user
   the URL it prints (`http://127.0.0.1:7878`). Don't force a browser open in case
   they're headless or on CI.
4. **Prove it works.** Trigger one real tool call (read a file, list a directory, or
   call an MCP server the user has). Then point them at the dashboard and tell them
   which verdict the call got and what it means (see Verdicts).
5. **Hand back.** Summarize: which agents are now protected, the dashboard URL, and
   the one command to undo everything (`agentguard uninstall`).

After `init`, some agents (Claude Code, Cursor) need a one-time restart to pick up
the rewritten config — tell the user if so.

## Operating playbook

- **Audit questions** ("what did my agent do?", "did anything get blocked?"): query
  the SQLite DB read-only at `~/.agentguard/data/agentguard.db`. The schema is in
  `~/.agentguard/data/SCHEMA.md` (auto-generated by the daemon). Prefer
  `agentguard tail --once` for a quick snapshot.
- **Policy changes:** use `agentguard policy list|show|enable|disable`. **Never**
  edit the YAML packs by hand — the CLI keeps the audit log and dashboard in sync.
- **Test a server for attacks:** `agentguard scan <server-command>` fires the canned
  injection corpus and exits non-zero if any reach the model surface.
- **Investigate a flagged call:** open `http://127.0.0.1:7878/calls/<id>` or read the
  row from the DB; the per-stage trail shows exactly which stage acted and why.

---

## Verdicts (explain these in one plain sentence to beginners)

- **allow** ✓ — the call passed every stage; it went through untouched.
- **flag** ⚠ — suspicious but not blocked; logged for review (e.g. a low-confidence
  injection signal).
- **transform** — the call was let through but modified, e.g. a leaked API key was
  redacted before forwarding.
- **block** ✗ — the call was stopped before reaching the model or the network, and
  the agent got a clean error explaining why.

---

## Safety rails (do not skip)

- Before **anything destructive** — `agentguard uninstall`, `agentguard policy
  disable`, `--purge` — confirm with the user first, in plain language.
- **Never weaken protection silently.** If a task would disable a stage, loosen a
  policy, or stop the daemon, say so and ask.
- Uninstall is reversible: it stops the daemon, then restores every config
  byte-for-byte from its `.agentguard.bak`. Reassure the user of this when they
  hesitate.

---

## Troubleshooting

- **`agentguard doctor` shows ✗:** read the remediation hint on the line; common
  cases are a missing `~/.agentguard` tree (re-run `init`) or a stale pidfile (it
  self-heals on the next `dashboard` start).
- **Re-install failed on Windows ("file already exists"):** a previous AgentGuard
  process was holding the binary. The current installer stops it automatically; if
  the user is on an old installer, have them run `agentguard uninstall` (which now
  stops the daemon) and re-install.
- **A tool call hangs after `init`:** the agent likely needs a restart to load the
  rewritten config. Restart the agent once.
